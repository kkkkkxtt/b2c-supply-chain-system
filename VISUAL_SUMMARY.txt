├─ id (VARCHAR PK)

🔐 BLOCKCHAIN INTEGRATION
═══════════════════════════════════════════════════════════════════════════════

EVENT 1: USER_IDENTITY_HASHED (Type 5)
┌─ Hash includes:
│  ├─ userId
│  ├─ role
│  └─ walletAddress ← NEW
└─ Hash Algorithm: SHA-256 → bytes32

EVENT 2: ITEM_METADATA_HASHED (Type 4)
┌─ Hash includes:
│  ├─ itemId
│  ├─ sellerId
│  ├─ sellerWallet ← NEW
│  ├─ name, description, price, stock, ...
│  └─ createdAt
└─ Hash Algorithm: SHA-256 → bytes32

EVENT 3: ORDER_CREATED (Type 0)
┌─ Hash includes:
│  ├─ orderId
│  ├─ amount
│  ├─ buyerId
│  ├─ buyerWallet ← NEW
│  ├─ itemId
│  └─ quantity
└─ Hash Algorithm: SHA-256 → bytes32

EVENT 4: STATUS_UPDATE (Type 1)
┌─ Hash includes:
│  ├─ orderId
│  ├─ shipmentId
│  ├─ location
│  ├─ updater
│  └─ updatedAt
└─ Hash Algorithm: SHA-256 → bytes32

🎓 ARCHITECTURE HIGHLIGHTS
═══════════════════════════════════════════════════════════════════════════════

  OFF-CHAIN (PostgreSQL)
  ├─ Full business data
  ├─ User profiles with wallet addresses
  ├─ Item catalog
  ├─ Order history
  ├─ Shipment tracking
  └─ Wallet balances

  ON-CHAIN (Hardhat Blockchain)
  ├─ Hashes only (no PII)
  ├─ Wallet addresses included in identity
  ├─ Entity keys indexed via keccak256
  ├─ Immutable proof of events
  ├─ Event timestamps
  └─ Sender addresses

  DATA FLOW
  1. User registers → wallet_address stored
  2. Item created → seller_wallet_address cached
  3. Order placed → buyer_wallet_address cached
  4. Data hashed → SHA-256 with wallet context
  5. Hash recorded → On-chain event emitted
  6. Proof stored → TX hash saved off-chain
