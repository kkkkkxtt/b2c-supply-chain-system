## 👥 Users Table

### New Fields Added

```sql
wallet_address VARCHAR(42) UNIQUE NOT NULL
contact_number VARCHAR(20)
created_at TIMESTAMPTZ
updated_at TIMESTAMPTZ
```

### Purpose

- **wallet_address**: Ethereum address (0x + 40 hex chars) generated by Hardhat account
  - Unique identifier for blockchain transactions
  - Cannot be modified after account creation
  - Used as identity proof on-chain
  - Displayed in user profile but not editable by frontend

### Database Integrity

- `wallet_address` has UNIQUE constraint
- Added index on `wallet_address` for fast lookups
- `role` field is immutable after creation
- User can update: name, email, contact_number, address

### Code Location

- Type: `types/user.ts`
- Queries: `lib/db/users.ts`
  - `registerUser()`: Creates user with wallet_address from parameter
  - `updateUser()`: Allows updating only mutable fields
  - `login()`: Validates with email
  - `getUserByEmail()`, `getUserById()`: Retrieve user info

## 📦 Items Table

### New Fields Added

```sql
seller_wallet_address VARCHAR(42) NOT NULL
updated_at TIMESTAMPTZ
```

### Purpose

- **seller_wallet_address**: Cached from seller's wallet_address for blockchain proof generation
  - Denormalized for performance (no additional JOIN needed)
  - Included in item metadata hash for on-chain verification
  - Cannot be modified (seller address is immutable)

### Update Timeline

- Items can be edited by seller (name, description, price, stock, image_url)
- `updated_at` automatically updated via database trigger

### Code Location

- Type: `types/item.ts`
- Queries: `lib/db/items.ts`
  - `createItem()`: Stores seller_wallet_address at creation
  - `updateItemBySeller()`: Updates mutable fields

## 🔐 Blockchain Proofs Table (Optional)

### New Table for Audit Trail

```sql
blockchain_proofs {
  id SERIAL PRIMARY KEY
  entity_id VARCHAR(255)           -- orderId, itemId, userId, shipmentId
  entity_type VARCHAR(50)          -- 'ORDER', 'ITEM', 'USER', 'SHIPMENT'
  event_type VARCHAR(50)           -- EVENT_* enum values
  data_hash VARCHAR(255)           -- SHA-256 hash (0x + 64 hex)
  blockchain_tx_hash VARCHAR(255)  -- Ethereum tx hash
  sender_address VARCHAR(42)       -- Account that recorded transaction
  proof_timestamp TIMESTAMPTZ      -- When proof was created
  created_at TIMESTAMPTZ
}
```

### Purpose

- Maintains complete audit trail of all blockchain operations
- Enables verification of on-chain proofs
- Optional but recommended for production systems

## 🔄 Hashing Strategy

### Data Hashed for Blockchain

**USER_IDENTITY_HASHED** (Event Type 5)

```json
{
  "userId": "user_id",
  "role": "BUYER|SELLER|LOGISTICS",
  "walletAddress": "0x..."
}
```

**ITEM_METADATA_HASHED** (Event Type 4)

```json
{
  "itemId": "item_id",
  "sellerId": "seller_id",
  "sellerWallet": "0x...",
  "name": "item_name",
  "description": "...",
  "price": 0.0,
  "stock": 10,
  "imageUrl": "...",
  "createdAt": "ISO_TIMESTAMP"
}
```

**ORDER_CREATED** (Event Type 0)

```json
{
  "id": "order_id",
  "amount": 0.0,
  "buyer": "buyer_id",
  "buyerWallet": "0x...",
  "item": "item_id",
  "quantity": 1
}
```

**STATUS_UPDATE** (Event Type 1)

```json
{
  "orderId": "order_id",
  "shipmentId": "shipment_id",
  "location": "current_location",
  "updater": "user_id",
  "updatedAt": "ISO_TIMESTAMP"
}
```

### Hash Computation

- Algorithm: SHA-256 (Node.js `crypto.createHash('sha256')`)
- Format: `0x` + 64 hexadecimal characters
- Size: 32 bytes (256 bits)
- Stored as: `bytes32` on-chain (OrderTracker.sol)
